## 1. 一言でいうと

**動線（歩く順の線）を地図に載せると道から外れて信頼を失う。  
線を消すと、初めての駅ではどこへ向かえばよいか分からず迷子になりやすい。**

このトレードオフを、散歩アプリとして解いてほしい。

---

## 2. プロダクトの前提

- 知らない駅の徒歩圏を、土地の文章（歩き方）に沿ってぶらり歩くアプリ。
- 地図は「ナビの最短ルート再現」が目的ではない。
- 思想に近い言葉: **歩き方は自由** · おすすめは教える · ラベルを貼りすぎない。
- 小回りはおおよそ **散歩のみ・約1時間**（ご飯・休憩店で時間を稼がない）。
- コースの骨は **土地ページの「歩き方」文**（walkGuide）。地図の点はそれに対応する立ち寄り。

**ユーザー像（この問題で特に重要）**

- その駅が **初めて**。土地勘がない。
- 番号付きのおすすめ点は見えるが、**次の点へどの道で行けばよいか**が分からないと不安。
- 線が街区・川・堀を斜めに切っていると、「このアプリの道は信用できない」と感じる。
- Apple Maps 標準の店アイコンが大量に出ると、アプリのおすすめ点と区別できない。

---

## 3. 問題（解決してほしいこと）

### 3.1 主問題

初めての駅でも **迷子にならず**、かつ **嘘の道（街区横断・水面横断・外周車道だけの線）を信じさせない** 地図表現を決める。

### 3.2 対立する要求

| 要求 | なぜ必要か | やりすぎると |
|------|------------|--------------|
| 向き・次の一歩が分かる | 初訪問で不安を減らす | ナビアプリ化し、土地の「ぶらり」が死ぬ |
| 道に沿った信頼できる線 | 「ここを歩け」と言える | MKDirections / OSRM が外周道路や川渡りを選び、城跡・境内の散歩感が消える |
| 敷地内（寺・公園・城跡）を感じる | 歩き方文が「一周・境内」と言う | 自前 polyline が駅から園まで直線になり、また道を切る |
| 地図がすっきり | おすすめ点が主役 | 線も向きも無いと初訪問で迷子 |
| 歩き方は自由 | 思想・体験の核 | 完全に自由だけだと「何も教えてくれない」 |

### 3.3 やってはいけない（現時点の学習）

1. **街区・建物・堀・川を斜めに切る直線**を「動線」として出す。
2. **一端が園内だから**駅〜園をすべて自前 polyline で結ぶ（道なりをスキップ）。
3. 園内を歩かせたいのに **MKDirections だけに任せ**、外周車道だけの線になるのを放置する。
4. 道なり地獄に入り、**線の修正を無限に繰り返す**（同じ症状ファミリーの対症）。
5. 「くわしく」地図で **Apple の店 POI を全表示**し、おすすめ点を埋もれさせる。
6. 矢羽をびっしり敷いて「動線がたくさんある」ように見せる（線と矢羽は別物）。

## 4. これまでに試したこと（時系列・要約）

| 時期 | 方針 | 結果 |
|------|------|------|
| 以前 | 道なり（MKDirections / OSRM foot）＋行きの実線 | 川を切らない点では改善。城跡は外周道路になり「散歩っぽくない」 |
| 2026-11-14 | 淀城跡に `grounds` corridor（園内 path）。園内は自前線優先 | 園内には入るが、駅→園が街区斜め横断。園内も折れ線で水面を切ることがある |
| 同日 | 駅→入口は MK、園内どうしだけ grounds＋短い道なり | 改善を試みたが、全体として線の信頼が回復しきらず |
| 同日 | **動線の線を廃止**。立ち寄り番号＋おすすめ通りは **点だけ**。字幕「歩き方は自由 · 点はおすすめ」 | 嘘の線は消えた。一方で **初訪問の迷子感**が残る／強まる懸念 |
| 同日 | 地図は常に Apple POI `.excludingAll`。くわしくはアプリのピン名だけ | 店アイコンのノイズは解消方向 |

**いまの実装（暫定）**

- iOS: `TourMapPage` は MapPolyline / MKDirections を呼ばない。点（コース番号＋atmosphere hint）のみ。
- Web: `StationMap.tsx` も OSRM 線を描かない。
- 関連コード: `WalkRouteBuilder.swift`, `AtmosphereCorridor.swift`, `TourMapPage.swift`, `StationMap.tsx`
- 知識ログ: `.cursor/rules/99-knowledge-log.mdc`（動線・grounds・POI・点だけ）

## 5. 望ましい体験（受け入れ条件）

満たせば成功、満たさなければ未達。

1. **初訪問でも次の向きが分かる**  
   駅（スタート）を出て、番号 1 の点へ向かうおおよその方向・手がかりがある（線でも、段階的な点でも、短い案内でも可）。

2. **地図上の「道」を信じられる**  
   ユーザーが「この線／この手がかりの通りに歩ける」と感じる。明らかな横断・水面切りがない。

3. **土地の歩き方と矛盾しない**  
   例: 「淀城跡の石垣と内堀の周りをぐるり」→ 外周車道だけ、または公園に一切入らない表現は不可。

4. **歩き方は自由のまま**  
   厳密なターンバイターンナビを強制しない。寄り道・引き返しが気持ちとして許される。

5. **すっきり読める**  
   Apple の店アイコンや矢羽の乱立で、アプリの点が埋もれない。

6. **全駅で同じ理屈**  
   淀だけ特例ではなく、寺・公園・商店街・川辺がある駅でも同じ仕様言語で説明できる。

## 6. 解の候補スペース（決め打ちしない · 他AIへの依頼）

次のいずれでも、または組み合わせでもよい。**採用はプロダクト側が決める。** 提案時はトレードオフを明示すること。

A. **信頼できる道なり線だけ**（取れない区間は線を切る／出さない）  
B. **粗い向きだけ**（駅→1 の方位矢印1本、区間中央に薄い矢印など。線は無し）  
C. **段階点**（通りの入口・橋の手前・門前など、線の代わりの中間おすすめ点）  
D. **敷地内は点の雲／短い弧だけ、街路は道なり**（ハイブリッドを仕様として固定）  
E. **地図は点、歩くタブに文章の順路**（「改札を出て南西へ…」）を大きく出す  
F. **ユーザーが線 ON/OFF**（既定は点、迷ったら線）  
G. **その他**（未提示のやり方歓迎。言い換えだけの案は不要）

各案について書いてほしいこと:

- 初訪問の迷子にどう効くか  
- 嘘の道リスク  
- 実装コスト感（iOS MapKit / Web Leaflet）  
- 思想「歩き方は自由」との相性  
- やってはいけないこととの衝突有無

## 10. 他AIレビュー · トレードオフと推奨組み合わせ（2026-11-14）

**核:** 地図に「未来の予定ルート（一本の線）」を引くのをやめ、**文章（walkGuide）と地図の役割を分ける**。  
ナビの線＝強制レール。散歩に必要なのは **改札後の最初の手がかり** と **土地の空気の輪郭**。

### 10.1 候補比較（要約）

| 案 | 迷子 | 嘘の道 | コスト | 自由 | 備考 |
|----|------|--------|--------|------|------|
| A 信頼できる道なりだけ | ○ | △ | 中 | △ | 外周車道化が残る |
| B 粗い向きだけ | △ | ◎ | 低 | ◎ | 矢印の先が川・壁だと迷う |
| C 段階点（ゲート） | ◎ | ◎ | 低〜中 | ◎ | 橋・門・踏切を0番に |
| D 敷地は点/弧＋街路は道なり | ○ | △ | 高 | ○ | 泥沼リスク |
| E 地図は点＋文章順路 | ○ | ◎ | 低 | ◎ | walkGuide 分割表示 |
| F 線 ON/OFF | ○ | △ | 中 | ○ | ONで嘘の線が残る |
| G1 視線コンパス | ◎ | ◎ | 低 | ◎ | 方位のみ。線なし |
| G2 敷地の面（ゾーン） | ○ | ◎ | 中 | ◎ | 城跡・境内・川辺を塗る |
| G3 歩いた軌跡のみ | ×単体 | ◎ | 低 | ◎ | 未来線は無し。事実だけ |

### 10.2 推奨組み合わせ（レビュー案）

1. **C + E** — 0番の入り口点（橋・門・踏切）＋地図下に walkGuide 1〜2行  
2. **G2** — 城跡・境内・川辺は線ではなく淡い面  
3. **G3** — 予定線は消したまま、歩いた軌跡だけ残す  

データ方針: ルート座標の連結より、**walkGuide 冒頭の入り口点＋立ち寄り1〜3の座標精度**に集中。

### 10.3 Cursor 感触（現行 iOS / Web への載せやすさ）

**いま組む軸は C + E。次に G2。G3 は後から足す。A / D / F は採らない。**

| 順位 | 案 | 理由 |
|------|-----|------|
| **1 · 今すぐ** | **C + E** | E は `station.walkGuide` と TourMap のフッター／歩くタブが既にあるので分割表示だけ。C は walkGuide 冒頭の「橋・門・踏切・鳥居」を 0 番スポット化するだけで、線エンジンを復活させない。iOS/Web 同じ型 |
| **2 · 続けて** | **G2** | 既存 `grounds` / riverside corridor の path を「面」に転用できる（厳密 OSM ポリゴンは後）。淀・境内問題の本丸。線を戻さない |
| **3 · 余韻** | **G3** | GPS 軌跡 Polyline は単純。迷子対策にはならないが「自分の散歩道」体験に直結。C+E のあと |
| 任意 | G1 | iOS は Heading で安い。Web は権限・対応がばらつくので二の次 |
| 見送り | A, D, F | 道なり地獄・ハイブリッド泥沼・嘘の線の温存 |

**実装（2026-11-14）:** 地図タブ下に walkGuide 先頭カード（E）＋「入」入り口点（C）を iOS/Web に入れた。面（G2）・軌跡（G3）は未着手。
