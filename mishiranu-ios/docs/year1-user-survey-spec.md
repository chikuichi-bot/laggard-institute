# 見知らぬ駅 · 1年利用後アンケート仕様書

**宛先:** アンケート設問を作成する AI（本仕様に沿って質問文・選択肢・分岐を完成させる）  
**発注側:** 見知らぬ駅（iPhone アプリ）制作  
**想定実施:** 本アプリをおよそ1年間使った利用者 **約100人**  
**言語:** 日本語（設問・選択肢とも）  
**文書の役割:** 設問の「正本」ではなく、**設問を作るための仕様・設計意図・網羅範囲**。設問文言は本仕様を満たす範囲で AI が起草してよい。

---

## 0. 他 AI への依頼文（そのまま渡せる）

次のブロックを、設問作成 AI に最初に渡してください。

```
あなたはプロダクトリサーチの専門家です。
添付の「見知らぬ駅 · 1年利用後アンケート仕様書」に従い、
約100人が回答する「1年利用後」の日本語アンケートを完成させてください。

必須成果物:
1. 回答者向けの導入文（短い）
2. 全設問（番号付き）・選択肢・回答形式・分岐条件
3. 推定所要時間と、短縮版（10分以内）の対応表
4. 分析用の変数名・尺度の対応表（スプレッドシート列案）
5. 「聞かないこと／聞き方を避けること」のチェックリスト遵守の自己点検

制約:
- 仕様書の製品理解・哲学・改善観点を落とさない
- 体験の質（降りた／見た／聴いた）と UI 改善の両方をきめ細かく聞く
- 誘導・褒め誘導・アプリ宣伝調を避ける
- 個人情報は最小限。位置の生ログは求めない
```

## 1. 調査の目的

### 1.1 一次目的
1年使った人の**実感**を集め、次の開発優先度を決める。

特に知りたいこと:

| 優先 | 知りたいこと |
|------|----------------|
| A | アプリの核（「名前だけの駅に降りる／土地が見える」）が、実際に起きているか |
| B | どの機能が継続利用の柱か、どれが形骸化しているか |
| C | つまずき・不信・がっかり・怖さ（安全・プライバシー含む） |
| D | 声の案内・地図・コース・物語など、改善の具体候補 |
| E | 推薦意向と、推薦／非推薦の理由の質 |

### 1.2 二次目的
- セグメント別の差（通勤／観光／散歩趣味／関西在住など）
- 「1年後も残っている印象」の言葉（プロダクトコピー・ストア文言の種）
- やめる／減った人の理由（継続者だけの美化を防ぐ）

### 1.3 この調査でやらないこと
- 広告効果測定・競合ベンチの本格比較（必要なら別調査）
- 個人を特定できる日記・移動軌跡の提出
- 開発チームへの直接クレーム窓口化（任意の自由記述は可）

## 2. 製品理解（設問作成 AI が必ず踏まえること）

### 2.1 一言
知らない（または名前だけ知っている）駅に降り、土地の案内を手がかりに散歩する iPhone アプリ。

### 2.2 思想の芯（設問の軸にする）
制作の根は「**名前を教えた瞬間、鳥を見なくなる**」に近い。

- 駅名というラベルだけで通り過ぎてしまうことへの違和
- 名前の向こうの土地・空気・道を、自分の足と目で取り戻すこと
- 感想を強要しない／ラベルを貼りすぎない余白も大事（アンケート自体が体験を壊しすぎないこと）

設問は「満足度」一辺倒にせず、**「見えるようになったか」「降りたくなったか」「また行きたくなったか」**を中心に置く。

### 2.3 主な体験フロー（機能マップ）
設問は次のモジュールをカバーすること。未使用モジュールは分岐でスキップ可。

| ID | モジュール | ユーザーがやること | 改善観点の例 |
|----|------------|-------------------|--------------|
| M1 | チュートリアル／初回理解 | 何のアプリか理解する | 長さ、詩的すぎ／説明不足、スキップ後の迷子 |
| M2 | 駅の特定 | 駅名入力／候補／現在地から最寄り | 誤駅、現在地失敗、圏外、候補のわかりにくさ |
| M3 | 到着・物語のゆかり | 駅にまつわる物語の断片に触れる | 面白さ、信頼、くどさ、長さ、続きが欲しいか |
| M4 | 土地ページ | 駅・エリア・寄るところ・歩き方などを読む | 文章の質、量、重複、地元感、誤り |
| M5 | 声の案内（読み上げ） | イヤホン等で歩きながら聴く | 声質、速さ、句点の間、誤読、途切れ、バッテリー、屋外でも聴けるか |
| M6 | 散策コース | コースを選び歩く | 距離・時間の妥当性、順番、ピンずれ、面白さ |
| M7 | 地図 | 徒歩圏・ピン・現在地 | 見やすさ、ピン精度、迷子、オフライン |
| M8 | 屋外利用 | 電車・改札外・電波の弱い場所 | 生成待ち、キャッシュ、エラー文、Mac不要で使えるか |
| M9 | 継続の習慣 | 何度も使う／季節・気分で使う | きっかけ、飽き、駅の枯渇感、新路線・新駅への期待 |
| M10 | 信頼・安全・倫理 | 個人情報、位置、課金・コイン、AI文章 | 不安、誤りへの対処、子ども・夜間の安心感、コインの納得感 |

### 2.4 想定ユーザー像（セグメント案）
設問作成時にスクリーニングまたは属性で取れるようにする。

- 関西在住／たまに関西に来る／ほとんど来ない
- 主な使い方: 日常の寄り道／観光／通勤の合間／散歩・記録趣味
- 利用頻度: 週1以上／月数回／年に数回／ほぼ使わなくなった
- 1年のうち「よく使った時期」があるか（引っ越し、旅行、季節）

## 3. 調査設計の枠

### 3.1 対象
- **包含:** 見知らぬ駅をインストールし、少なくとも数回は駅を開いた／歩いた経験がある人。理想は「約1年の利用歴」だが、**利用開始から8〜14か月**程度も可とする。
- **除外候補（スクリーニングで分岐）:** 開いただけで終わった人 → 短縮版（離脱理由中心）へ。

### 3.2 サンプル
- 目標回答数: **100**（有効回答）
- 内訳の努力目標（厳密割付は必須でない）:
  - 継続利用者（直近3か月に1回以上）: 60前後
  - ヘビー（月2回以上）: 20前後を含む
  - 離れ気味／休眠: 20〜30（理由分析のため必須に近い）

### 3.3 形式・所要時間
- 主形式: オンラインアンケート（Googleフォーム／Typeform／自前などツールは問わない）
- **本編目標: 15〜20分**（中央値）。超える場合は必須／任意を明示。
- **短縮版: 8〜10分**（休眠・離脱向け、または途中離脱防止用コア設問）。
- 端末: スマホ回答を主想定（長文は任意）。

### 3.4 尺度の統一（作成 AI はこれに合わせる）

| 記号 | 意味 | 使い方 |
|------|------|--------|
| L5 | 1〜5（低い↔高い／そう思わない↔そう思う） | 態度・満足・頻度感 |
| L7 | 1〜7 | NPS 風の推薦度のみ推奨 |
| F | 頻度選択肢（例: ほぼ毎日／週に数回／…／使っていない） | 行動 |
| MC | 単一選択 | 属性・主用途 |
| MA | 複数選択（上限を書く場合あり） | 理由・改善候補 |
| OE | 自由記述（短／中／長を指定） | 印象・エピソード・改善 |
| MATRIX | 行=項目・列=L5 | 機能別評価 |

**NPS:** 「親しい人に勧めるか」0〜10。理由は必須の短い OE。

### 3.5 倫理・トーン
- 冒頭で: 目的、所要時間、匿名性、位置情報を提出させないこと、途中離脱可。
- 責めない／正解を求めない。詩的すぎる設問で回答者を疲れさせない。
- 「名前を忘れる」思想を**回答者に説教しない**。行動と実感で測る。
- ネガティブ選択肢を必ず対等に置く（「特にない」も可）。

## 4. アンケート構成（セクション仕様）

作成 AI は **S0〜S12** をすべてカバーする設問セットを作ること。  
各セクションに「必須コア」「深掘り（任意 or 分岐）」「自由記述」を設ける。

### S0. 導入・同意・スクリーニング
**意図:** 対象者の確認、負荷の予告。

必須に含める要素:
- アプリ名の確認（見知らぬ駅）
- おおよその利用開始時期（年月または「およそ○か月前」）
- 直近3か月の利用有無
- 同意（匿名集計・改善目的）

分岐:
- 直近3か月ゼロかつ開始から短い → 短縮版へ
- 「インストールしたが駅をほとんど開いていない」→ 離脱理由セットへ

---

### S1. 全体の印象（1年後に残っているもの）
**意図:** 機能より先に、記憶に残る体験を取る。

必須コア:
- このアプリを一言で言うと（OE 短、例: 20〜40字目安）
- いちばん印象に残っている駅 or 散歩（OE 中。駅名は任意で伏せてもよい）
- 「名前だけ知っていた場所が、自分の場所になった」感覚の有無（L5）
- 全体満足（L5）と、その理由の種（MA + OE 任意）

深掘り:
- 1年前の自分に勧めるか（L5）
- 期待と違った点（MA）

---

### S2. 利用の実態（行動）
**意図:** ヘビー／ライト／休眠の実態。

必須コア:
- 利用頻度（F）— 最盛期と直近を分けて聞くのが望ましい
- 主な利用シーン（MA）: 通勤の合間、観光、休日の散歩、旅行先、夜、雨の日、など
- 一度の利用で歩くおよその時間（MC）
- 利用エリア感（MA）: 京阪沿線、大阪、神戸、その他関西、関西以外（将来含む）

深掘り:
- 季節や気分で使い方が変わるか（L5 + OE）
- 「駅を使い果たした」感覚（L5）

---

### S3. 核体験の達成度（哲学の検証）
**意図:** 仕様書 2.2 がユーザー側で起きているか。

必須コア（いずれも L5 + 必要なら短い OE）:
- 知らない駅に**実際に降りた**回数感（F または段階）
- 「降りてよかった」と思った頻度（L5）
- ラベル（駅名）だけで終わるのではなく、土地の様子が目に入るようになったか（L5）
- また同じ土地を歩きたくなったか（L5）
- アプリなしでも、見知らぬ駅に降りたくなる癖がついたか（L5）※重要

深掘り:
- 逆に「アプリがあるのに降りなかった／すぐ戻った」経験（MA: 時間がない、怖さ、誤り、退屈、電波、など）

---

### S4. チュートリアル・初回理解（M1）
**意図:** 初回の理解コストとトーンの適否。

必須コア:
- 初回に「何をするアプリか」分かったか（L5）
- チュートリアルの長さ（短すぎ／ちょうど／長すぎ）
- トーン（詩的・説明的のバランス）（MC または L5）

深掘り:
- スキップしたか。スキップ後に困ったか
- 覚えている一文があれば（OE 任意）— コピー改善の種

---

### S5. 駅の探し方・現在地（M2）
**意図:** 入口の摩擦。

必須コア:
- よく使う入り口（MC/MA）: 駅名検索、候補から、現在地、その他
- 駅の取り違え経験（F）
- 現在地が使えなかった／遅かった経験（F）とそのときどうしたか（MA）

深掘り:
- 候補の並び・表記の分かりやすさ（L5）
- 「この駅は載っていない」と感じた経験（F + OE）

---

### S6. 物語のゆかり・文章の信頼（M3/M4）
**意図:** コンテンツ品質と信頼。

必須コア（MATRIX 推奨）:
行例: 駅の紹介、エリアのこと、寄るところ、物語のゆかり、歩き方  
列: 面白さ／役立ち／くどさの少なさ／信じられる（各 L5）または「使った／読んでいない」

加えて:
- AI／自動生成っぽさへの違和（L5）
- 事実誤認・ピンずれ・「地元の人ならおかしい」と感じた経験（F + OE）
- もっと欲しい情報（MA）: 歴史、店、自然、安全、写真、短さ、子ども向け、夜間、バリアフリー 等

---

### S7. 声の案内・聴きながらの散歩（M5）
**意図:** xVoice／読み上げ体験の改善点をきめ細かく。

未使用者はスキップ可。使用者には必須コア:

- 使用頻度（F）
- 総合（L5）
- 声の好み（L5）: 自然さ、速さ、聞き取りやすさ
- **句点のあとの間**（短すぎ／よい／長すぎ）※リズム改善の継続指標
- 歩きながら聴けるか（L5）: 画面を見ずに済むか
- 途切れ・待ち・再生の不安定（F）
- 誤読・固有名の読み（F）
- イヤホン有無、公共の場での使いづらさ（MA）
- バッテリー・通信への影響の体感（L5）

深掘り OE:
- 「この声の案内で助かった瞬間」「イライラした瞬間」

---

### S8. コースと地図（M6/M7）
**意図:** 歩く体験の設計ミスを取る。

必須コア:
- コースを選んで歩いたか（F）
- 距離・所要の妥当性（L5）
- 順番・寄る場所の納得感（L5）
- 地図の見やすさ（L5）
- ピンの位置精度の体感（L5）: 川の上、校庭の中、などズレ経験（F + OE）
- 現在地表示との関係で迷ったか（F）

深掘り:
- 「コースに従わず土地ページだけ読む」派か（MC）
- 欲しいコース種（MA）: 短い／長い、雨天、夜、子連れ、写真向き、寺社多め、商店多め 等

---

### S9. 屋外・通信・エラー（M8）
**意図:** 実地で壊れないか。

必須コア:
- 電波の弱い場所・地下・車内での失敗（F）
- エラーメッセージの分かりやすさ（L5）
- 「外では使えない」と感じたことがあるか（L5）
- 一度 Wi‑Fi 等で開いた駅が、後から外で開けたか（分かる人だけ）

---

### S10. 継続・習慣・離脱（M9）
**意図:** 1年後の関係性。

必須コア:
- 今の関係（MC）: よく使う／たまに／休眠／やめた
- 続ける理由（MA、継続者）
- 減った・やめた理由（MA、休眠・離脱）※必ず対等な分量で聞く
  - 例: 時間が無い、駅が尽きた、文章が退屈、バグ、怖さ、他アプリで足りる、関西を離れた、料金、通知がない、など
- 戻ってくるとしたら何があれば（OE／MA）

深掘り:
- 新機能の期待（MA、優先度付きまたは上位3つ）:
  - 他地方の駅、お気に入り、歩いた記録、共有、ウィジェット、Watch、オフライン強化、声の種類、短時間コース、季節イベント 等

---

### S11. 信頼・安全・プライバシー・お金（M10）
**意図:** 長く使う前提の不安。

必須コア:
- 位置情報の使われ方への安心（L5）※「端末内で最寄り検索」等の説明を読んだ上で答えさせる短文を添えてよい
- 個人アカウント不要であることの評価（L5）
- 子ども・夜間・一人歩きの安心感（L5、該当者）
- 課金・コイン（散歩道を開く等）の分かりやすさ・納得感（L5）※「物語のゆかりまで無料／散歩道でコイン」など、現状ルールを短く添えてから聞く
- 買い切り・追加課金・サブスクへの意向（MC）※仮定質問は「仮定」と明記
- 不正確な案内で困った／危険を感じた（F + OE）

---

### S12. 推薦・クロージング
**意図:** 優先度付けと余韻。

必須コア:
- 推薦度 0〜10（L7 相当）
- その点数の理由（OE 必須・短）
- 改善してほしいこと上位（MA 最大3 + OE）
- 「消さないでほしいもの」（OE または MA）— 改悪防止
- 最後に一言（OE 任意）

謝辞・連絡（任意・オプトインのみ）:
- 追加インタビュー可否（メール等は最小・別フォーム推奨）

## 6. 分岐ロジック（必須）

作成 AI はフローチャートまたは疑似コードで分岐を明示すること。最低限:

```
S0 利用実態
  ├─ ほぼ未使用 → 離脱理由セット（短縮）→ S12 一部 → 終了
  ├─ 休眠（直近3か月ゼロ） → S1 短縮 + S10 厚め + S12
  └─ 継続
        ├─ 声を使った → S7 フル
        └─ 声未使用 → S7 は「なぜ使わないか」のみ
        ├─ コースを歩いた → S8 フル
        └─ 地図／文章中心 → S8 短縮
```

## 7. 分析・成果物の使い方（発注側）

設問作成 AI の出力を受けたあと、人間側で行う想定:

1. パイロット 5〜10人で文言修正
2. 100人回収

## 9. 文言トーンの見本（強制ではない）

よい例:
- 「このアプリを使って、名前だけ知っていた駅に実際に降りたことはありますか。」
- 「土地の案内を声で聴きながら歩いたとき、句点のあとの間（無音）はどう感じましたか。」

避けたい例:
- 「私たちの革新的な体験にどのくらいご満足ですか。」
- 「名前を忘れる哲学が理解できましたか。」（説教・テストになる）

## 11. 発注側メモ（設問 AI には渡してもよい）

- 声の案内は改善サイクル中（間・速度・安定性）。S7 は特に粒度高く。
- ピンずれ・駅中心ずれは既知の痛みになりやすい。S8 で具体例を拾えるとよい。
- 屋外利用は「さくらキャッシュ」前提の設計思想あり。技術用語は回答者に出さない。
- アンケート自体が「感想の強要」にならないよう、任意記述を多用しすぎない。核心は選択式で足りるようにする。
