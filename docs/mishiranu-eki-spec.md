## 1. 目的

地図アプリや口コミ検索の代替ではなく、「知らない駅に降りたあとの寄り道」を短時間で立ち上げる体験をつくる。

- 検索疲れを終わらせる（時間帯・滞在・徒歩圏で切る）
- 有名スポット偏重を避ける（駅から歩けるローカルを優先）
- 「何もない駅」を失敗ではなく、空白の肯定として扱う

姉妹プロダクト「おみくじ文庫」と同じ Lagado の空気感（和紙・明朝・偶然の出会い）を、駅と徒歩圏の物語に転用する。

## 2. 想定ユーザー

| ペルソナ | 状況 | 欲しいこと |
| --- | --- | --- |
| ふらり旅人 | 乗り換えた駅で時間が余った | 1〜3時間で回れる寄り道 |
| 日帰り散策 | 半日だけ土地を味わいたい | 歩く順番つきの短いコース |
| 空白の駅に降りた人 | 観光地が少なそう | 「何もない」を否定しない案内 |
| 編集・体験検証者 | Lagado Lab 内 | 文面・UI・AIの感触確認 |

当面の公開範囲は **Private（本人のみ）** の Cursor App、および研究所サイト上の Lab ページ。

## 3. 体験フロー（必須）

```
ヒーロー
  └─ 知らない駅に到着
       └─ 会話: 駅を決める
            ├─ 現在地で駅を探す
            └─ 駅名で探す（編集リスト / AI生成）
                 └─ いまの時間帯
                      └─ 滞在時間（1時間 / 3時間 / 半日）
                           └─ 徒歩コースを1つ選ぶ（約3案）
                                └─ 物語・地図・案内板
                                     ├─ とりあえずここに行け（シークレット）
                                     ├─ コピーを引き直す
                                     └─ 物語をコピー
```

### 3.1 画面

| 画面 | 役割 |
| --- | --- |
| ヒーロー | ブランド「見知らぬ駅」と CTA。出しすぎない第一画面 |
| 到着の会話 | 駅・時間帯・滞在・コースをチップ／入力で決める |
| 物語（ツアー） | **表示順:** 地図 → 観光案内 → このエリアのこと・歴史 → 観光案内メモ → COURSE → ご飯／お土産／観光／休むところ／寄り道 → レンタサイクル |

### 3.2 会話の段階

| 段階 | 入力 | 結果 |
| --- | --- | --- |
| `station` | 現在地 / 駅名検索 / 自由入力 | 編集駅または AI 生成駅 |
| `clock` | 「いまの時刻」または朝〜夜 | `DayPart` |
| `stay` | 1時間 / 3時間 / 半日 | 徒歩圏半径とスポット集合 |
| `mealSolo` | 一人で入りたい / 人数は気にしない / みんなで寄りたい | ご飯の一人可否希望 |
| `mealBudget` | 気軽に / 少し奮発 / どちらでも | ご飯の予算希望 |
| `course` | 3コースから1つ | 行程つきの歩き案（希望でご飯寄りを優先） |

入力欄でも同じ段階を進められる（駅名マッチ、時刻表現、「ゆる歩き」など）。

## 4. 機能仕様

### 4.1 駅の決定

1. **編集キュレーション**  
   手書きの駅シード（現状 **24駅**）。リストに一致すれば API コストなし。
2. **現在地**  
   ブラウザ Geolocation は端末内だけで照合。編集駅が半径 **3.5 km** 以内ならそれを採用。  
   遠い場合は座標をサーバへ送らず、駅名入力（編集リスト / AI）へ誘導する。
3. **任意駅名**  
   `POST /api/mishiranu/station`。編集リスト外は Gemini（任意で Google 検索グラウンディング）で徒歩圏案内を生成。

### 4.2 時間と半径

| 滞在 ID | 表示 | 半径（駅ごと `radiiKm`） | コース予算の目安 |
| --- | --- | --- | --- |
| `1h` | 1時間 | 第1値 | 約55分 |
| `3h` | 3時間 | 第2値 | 約150分 |
| `half` | 半日 | 第3値 | 約240分 |

時間帯（`DayPart`）はご飯スポットの朝／昼／夜フィルタと、コース開始の目安時刻に使う。

### 4.3 徒歩コース

滞在と時間帯から、スポットを並べ替えて **最大3コース** を提示する。

| コース骨格 | ねらい | 優先カテゴリ |
| --- | --- | --- |
| ゆる歩き | 景色と休み | 観光・休む・寄り道 |
| 食べる寄り道 | ご飯と土産 | ご飯・お土産・休む |
| 少し先まで | 徒歩圏の端 | 寄り道・観光・ご飯 |

各ストップは名称・種別・徒歩分・滞在目安・短い説明・任意の時計ラベルを持つ。タップで地図／詳細と連動する。

### 4.4 観光案内（カテゴリ）

案内板と凡例は次の5種。色とアイコンで識別する。

| `GuideKind` | 表示 | 役割 |
| --- | --- | --- |
| `meal` | ご飯 | 食べる（庶民的／高級 × 朝昼夜） |
| `souvenir` | お土産 | 手土産・買いもの |
| `sight` | 観光 | 見る・歩く見どころ（編集駅は実在の観光地を目安 2〜4件） |
| `rest` | 休むところ | カフェ・ベンチ・滞在の息継ぎ |
| `tip` | 寄り道 | 上記に収まらない小さな発見 |

必須の周辺案内として **レンタサイクル**（あり／未確認、場所・徒歩分・メモ）を別セクションで出す。

### 4.5 物語コピー

- 編集シードの `tourTitle` / `catchCopy` / 空白肯定文を既定とする。
- `GEMINI_API_KEY` があるとき `POST /api/mishiranu/copy` でタイトル・キャッチ等を生成し直せる。
- 「物語をコピー」で駅名・タイトル・キャッチ・滞在メタをクリップボードへ。

### 4.6 地図

- OpenStreetMap 系タイル上に駅中心と案内ピン。
- ピン色は `GuideKind` に対応。
- 選択スポット／コース停止と同期。

### 4.7 シークレット

「とりあえずここに行け」で、表示中スポット集合から1件を抽選し、詳細を開く。失敗させないための小さな決断装置。

### 4.8 空白肯定（`mood: "empty"`）

観光地が薄い駅向け。空の地図トーンと、否定しない見出し／本文を出す。失敗画面にしない。

### 4.9 エリアの厚み

駅シードおよび `withAreaDepth` による追記で、次を任意表示する。

- 駅イントロ
- 歩き方の目安
- 観光案内メモ
- エリア・歴史メモ
- レンタサイクル

## 5. データモデル（要約）

### 5.1 `StationSeed`

| フィールド | 意味 |
| --- | --- |
| `id` / `name` / `line` / `prefecture` / `region` | 識別と表示 |
| `mood` | `story` \| `empty` |
| `radiiKm` | `[1h, 3h, 半日]` の km |
| `stationIntro` / `areaAbout` / `walkGuide` | 文章 |
| `historyNotes` / `sightseeingNotes` | `{ title, body }[]` |
| `bikeRental` | 有無・要約・場所リスト |
| `tourTitle` / `catchCopy` / `emptyCopy` | 物語 |
| `spots` | スポット配列 |
| `lat` / `lng` | 任意（AI駅など） |
| `source` | `seed` \| `ai` |

### 5.2 `Spot`

| フィールド | 意味 |
| --- | --- |
| `id` / `name` / `blurb` / `detail?` | 表示 |
| `walkMinutes` | 駅からの徒歩目安 |
| `guide` / 旧 `genre` | 案内種別（未設定時は genre から推定） |
| `mealTier` / `mealTimes` | ご飯の価格帯・時間帯 |
| `soloOk` / `budgetYen` | 一人で入りやすいか・予算目安（例: 〜¥1,500） |
| `hours` | 営業・開館（わかるものだけ） |
| `lat` / `lng` | 地図ピン |

### 5.3 編集駅（現行）

出町柳、中書島、石清水八幡宮、大山崎、美瑛、蟹田、通洞、佐原、真鶴、浜金谷、長瀞、勝沼ぶどう郷、小淵沢、姨捨、下諏訪、由比、根府川、餘部、尾道、三角、臼杵、人吉、月崎、玉造温泉（**24**）。

## 6. API 仕様

いずれも Private アプリでは閲覧者 identity が必要。キー未設定時は編集データ／フォールバックで動く。

| メソッド | パス | 用途 | 制限の目安 |
| --- | --- | --- | --- |
| `POST` | `/api/mishiranu/nearby` | 現在地→駅 | 6回/分/閲覧者 |
| `POST` | `/api/mishiranu/station` | 駅名→案内 | 8回/分/閲覧者 |
| `POST` | `/api/mishiranu/copy` | 物語コピー生成 | 20回/分/閲覧者 |

### 6.1 nearby

- 入力: `{ lat, lng }`
- 出力: `{ station, source: "seed"|"ai", km? }`
- 編集駅が 3.5 km 以内なら seed。それ以外は Gemini（キー必須時）

### 6.2 station

- 入力: `{ name }`（最大40文字目安）
- 出力: `{ station, source }`
- 名前が編集リストに一致すれば seed。否则 Gemini

### 6.3 copy

- 入力: 駅・滞在など（実装に準拠）
- 出力: タイトル／キャッチ等
- 失敗時は編集コピーを UI 側で継続表示

### 6.4 AI

- モデル: **Gemini 3.1 Flash-Lite**（おみくじ文庫の AI 解説と同系統）
- 秘密: `GEMINI_API_KEY`（ホストの App Secrets）
- コスト感（概算）: 生成1回あたりおおよそ数円未満〜十数円弱。編集駅は無料

## 7. UI / デザイン方針

おみくじ文庫と揃えた **文学アプリの紙面**。

| トークン | 値の目安 |
| --- | --- |
| 背景 | `#f5eedc`（和紙） |
| カード | `#f9f4e6` |
| 罫線 | `#e3d5c1` |
| 本文 | `#2b2722` |
| 補助 | `#827b72` |
| 主ボタン | 墨塗り（本文色）× 紙色文字 |
| 朱アクセント | `#b5493a`（キッカー・ガイド） |
| 藍アクセント | `#6b8cca`（チップアイコン等） |
| 角丸 | 16px 前後 |
| 書体 | 明朝系ディスプレイ（Shippori Mincho 等） |

ルール:

- 第一画面はブランドをヒーロー級に。ダッシュボード化しない
- カードは操作単位に限定し、装飾カードを増やさない
- 案内種別は色＋線画アイコンで揃える
- 縦書き全文UIにはしない（文庫は縦書き、本アプリは横書きの紙面）

## 8. 非機能

| 項目 | 方針 |
| --- | --- |
| 認証 | Cursor Apps の identity（Private） |
| レート制限 | 閲覧者単位の短窓＋**有料 Gemini 呼び出し1回ごと**の時間予算、プロセス全体の同時実行／分予算。カウンタは一時ディレクトリへ永続化 |
| 位置情報 | 精密GPSはブラウザ内のみ。編集駅3.5km以内なら端末で照合。遠い場合は座標を送らず駅名入力を促す |
| キャッシュ | 生成結果は `private, no-store` |
| 静的公開 | 研究所サイト向けは API なしでも編集コピーで読める想定 |
| アクセシビリティ | チップ・案内項目はボタン、`aria-*` で段階を示す |
| iPhone / モバイル | `viewport-fit=cover`、Safe Area、48pxタッチ、入力16px、地図のタッチズーム、ホーム画面用アイコン |
| セキュリティ | Gemini キーは `x-goog-api-key`、POST は `application/json` 必須。永続レート制限は未実装 |

## 9. 非目標（当面やらない）

- 課金・マルチユーザー同期

## 11. 成功指標（プロト）

定量より「温度」。次が満たせれば MVP 成功とみなす。

1. 知らない駅でも、3分以内に「歩ける物語」が立ち上がる
2. 空白の駅で寂しさではなく、静かな肯定が残る
3. おみくじ文庫ユーザーが「同じ家の別部屋」と感じる見た目と余白
4. 編集駅では API なしでも一通り遊べる
