ホームページを世界に届ける「玄関と道路」。初心者でも、できることだけ掴めば十分です。

何ができる？ lagado.jp での分け方

まず一言

サーバーそのもの、ではない

Cloudflare は「サイトを置く箱」というより、世界中の近道・受付・看板に近いサービス群です。箱（さくら・ロリポップ）と組み合わせて使います。

できること

初心者が触るなら、この5つ

全部覚える必要はありません。lagado.jp では上から3つが中心です。

  1. 01
    DNS（住所の管理） 「lagado.jp を開いたらどこへ行くか」を決めます。引っ越しのスイッチになります。
  2. 02
    Pages（静的サイト公開） HTML やビルドした研究所サイトを、無料〜安価に世界公開。PHP は置けません。
  3. 03
    経路の振り分け（Rules / Workers） 同じ lagado.jp のまま、「研究所は Pages」「おみくじはさくら」と道を分けられます。
  4. 04
    R2（大きなファイル置き場） 動画など重いものを安く置く倉庫。PHP の代わりにはなりません。
  5. 05
    CDN・セキュリティ（おまけで付く安心） 速く届ける・変なアクセスを減らす。今の lagado.jp にも Cloudflare の看板は既に掛かっています。

あなたの計画

メインは Cloudflare、DB と PHP はさくら

この分け方は可能です。アプリの URL（おみくじ／Fragments）を変えなくて済むように、パスで振り分けるのが安全です。

Cloudflare

  • 研究所のホームページ（静的）
  • ドメイン DNS
  • 必要なら動画を R2
  • 「この道はさくらへ」の振り分け

できないこと：おみくじ／Fragments の PHP と sqlite をそのまま動かす

さくら

  • /omikuji_bunko/ の PHP と DB
  • /fragments/ の PHP と parts DB
  • プライバシー用 PHP（必要なら）

ライトで足りやすい。SSH／cron は日常にはほぼ不要

用語メモ

画面で見る言葉

ダッシュボードで迷いやすい言葉だけ。

Pages
静的サイトを置く場所。研究所向き。
Workers
小さなプログラム。URL の振り分けなどに使う。
R2
ファイル倉庫。動画・大きな画像向き。
DNS / ネームサーバ
住所録。ここを Cloudflare にすると振り分けが楽。
プロキシ（オレンジ雲）
Cloudflare 経由で届けるスイッチ。ON が一般的。

  • Images / Stream（専用の画像・動画製品）
  • Zero Trust / WARP（会社向けリモート）
  • AI・Vectorize など最新枠
  • 複雑な課金プランの最適化

次の一歩

この順で進むと迷いにくい

  1. さくらを契約して PHP＋DB を載せる 仮のアドレスで、おみくじ／Fragments が動くことを確認。
  2. Pages に研究所を載せる 今の静的ビルド（lolipop 出力相当）を置く。
  3. lagado.jp の道を分ける 研究所 → Pages、おみくじ／Fragments → さくら。
  4. 安定したらロリポップを降りる 急ぎで解約しない。切り替えて数日見てから。
