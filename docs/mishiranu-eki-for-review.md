# 見知らぬ駅（Mishiranu Eki）— 他AI向け評価用仕様

| 項目 | 内容 |
| --- | --- |
| 版 | **2.0**（2026-11-13） |
| 目的 | **電車内の数十秒〜2分で、「知らない駅の改札を出る決断」ができるか**を第三者に評価してもらう |
| ひとこと | 知らない駅に降りる。土地の歴史と今をガイダンスで聴きながら、小回り、大回りして散策する。撮影地や文学の舞台があれば土地に載せる |
| 物語サイト | https://lagado.jp/mishiranu-orikata/ |
| 形態 | **ネイティブ iOS** ＋ Web ラボ（Next.js）。地図は iOS では Apple MapKit |
| UIトーン | おみくじ文庫系の**和紙・明朝・余白**を維持（ダッシュボード化しない） |

この文書は実装の細部より、「何を約束し、何を約束しないか」と、**降りる決断に効く設計**を共有するためのものです。  
v1.0 からの主な更新: 成功基準を「案内がある」から **「ドアが閉まる前に降りられる」** へ明確化。無料輪郭→有料詳細、空白の肯定、撤退ラインを仕様に固定。

---

## 0. いちばん大切な評価基準（これ以外は枝）

機能の多さでも、UIの美しさだけでもない。

> **電車に乗っている人が、知らない駅の改札を出る決断ができるかどうか。**

猶予は多くの場合 **数十秒〜2分**（次駅アナウンス〜ドア）である。  
ここで「コイン消費＋長時間生成待ち」だけだと、人は降りない。

評価時は、すべての機能をこの一文に照らしてほしい。

---

## 1. 解こうとしている問題

電車に乗っていると、名前だけ知っている駅がいくつも通り過ぎる。気になっても、多くの人は降りない。

よくある理由は勇気不足ではなく、次の **3つのブレーキ**である。

| ブレーキ | 中身 |
| --- | --- |
| **時間** | 詳しく調べているうちにドアが閉まる |
| **空白への恐怖** | 降りたら何もなく、ホームに立ち尽くす想像 |
| **撤退への不安** | 迷子・帰れない・遠すぎる |

ネットでは情報が偏る（情報の非対称）:

| 情報が多い | 情報が少ない |
| --- | --- |
| 有名観光地、ランキング店 | 小さな駅前、地元の食堂、川沿いの道 |

調べるほど有名地ばかりが返り、**いまの駅から歩ける範囲**は空白のままになりやすい。

---

## 2. プロダクトの定義

### これは何か

- **駅に降りた直後の徒歩圏ガイド**（土地の話・地図・ご飯／土産／観光／休み・歩く順番）
- 「何もない駅」を失敗にせず、**歩く口実を1つでも残す**装置
- 名所の全国カタログではなく、**いまの駅から歩けるものだけ**を扱う

### これは何かではない（非目標）

- 乗り換え・時刻表API・予約・口コミスコアのアプリではない  
- ターンバイターンのナビ最適化ではない  
- Google Places 的な全国自動収集の完成形ではない  
- 「その土地のすべてを知っている地元人」の代替ではない  
- 曖昧な「気配」だけのエンタメではない（決断に効かない前情報は出さない）

---

## 3. 想定ユーザーと成功の定義

| 誰 | 状況 | 成功するとどうなるか |
| --- | --- | --- |
| 車窓の人 | 「次、降りてみようかな」 | **ドアまでに**、降りる／降りないが決まる |
| ふらり旅人 | 乗換で時間が余った | 30分〜3時間、駅の外へ出られる |
| 空白の駅に降りた人 | 店が少なそう | 「何もない＝失敗」にならず、風景を歩く |

**成功指標（温度）**

1. **初速:** 駅名確定〜輪郭（または正直な「材料不足」）が、コインなしでほぼ即出る  
2. **決断:** 輪郭または詳細のどちらかで、「降りて歩ける／やめておく」が選べる  
3. **信頼:** 地図ピンが徒歩圏外の誤位置だらけにならない  
4. **空白:** 店0でも失敗画面に見えず、散歩の口実が残る  
5. **撤退:** 「すぐ戻れる距離」「帰りの本数の気配」が分かる（不確かなら出さない）

## 4. 体験フロー（現行・仕様）

```
トップ（ブランド＋抽象地図）
  ├─ 現在地で駅を探す
  └─ 駅名で探す → 候補（カタログ＋地図）を選ぶ
       │
       ├─【保存済み】→ すぐ案内タブ（コイン0）
       │
       └─【未保存】
            ├─【無料】MapKit 輪郭（駅座標＋決断に効く材料だけ）
            │     ・材料あり → 具体名＋徒歩分などで確認
            │     ・材料なし → 偽の「気配」は出さず「詳しく調べますか？」だけ
            │
            └─ ユーザーが「詳しく調べる」→ コイン1（または BYOK）
                 └─ AI 本案内 → タブ:
                      土地 / 地図 / 案内 / 歩く / 設定
```

| タブ | 役割 |
| --- | --- |
| 土地 | 土地の成り立ち・雰囲気。冒頭に撤退一行（`railHint`、確信時のみ）。音声あり |
| 地図 | 徒歩圏のピンと歩く線。**unverified は出さない** |
| 案内 | 観光・ご飯・お土産・休むところ・寄り道。各行に徒歩分（すぐ戻れる距離感） |
| 歩く | コース（地形・名所・町場の役割雛形） |
| 設定 | 作り直し、見た目、料金、物語HP |

**重要:** 新規駅では、**本生成はユーザーの明示タップ後のみ**。輪郭取得と同時にコインを自動消費しない。

## 5. 「降りられる」を支える設計（核心3点）

### 5.1 ドアが閉まる前の初速（無料輪郭）

| やる | やらない |
| --- | --- |
| 駅確定直後、MapKit だけで駅位置＋具体的な寄り道（川名・公園名＋徒歩分）や店密度の分岐 | 「川と橋の気配があります」系の汎用文 |
| 決断に効く材料が無いときは、正直に「地図だけでは足りない」＋詳しく調べる確認 | 商業施設・駅名そのもののピンで輪郭を飾る |
| 詳しく調べる＝コイン（または自分の API） | 輪郭段階での有料強制 |

### 5.2 空白の肯定（店がない駅）

- 無理に店・名所を捏造しない。`mood: empty` と landform（川・坂・橋・田畑の道）を散歩の口実にする  
- spots が 1〜2 件でも失敗表示にしない  
- 遠方チェーン・隣駅の店で枠を埋めない  

### 5.3 撤退ライン（帰れる・歩ける）

- 案内の各スポットに **駅からの徒歩分＋目安距離（すぐ戻れる）**  
- 土地タブ冒頭に、確信があるときだけ **運行・規模の一行**（`railHint`）  
  - 例:「都市近郊・帰りは本数多め」「本数が少ない路線・改札前に帰り時刻の確認を」  
  - 不確かなら **出さない**（嘘の安心を作らない）

## 6. 地図と座標の約束

| 信頼 | 意味 | 地図 |
| --- | --- | --- |
| lock | 人手で固定した正本 | 出す |
| apple | MapKit 等で駅近傍にヒット | おおよそ **1.5km 以内**なら出す |
| unverified | 未確認・遠すぎ | **地図に出さない**（案内文には残せる） |

駅中心は、鉄道駅らしいヒット以外（神社だけの同名など）を拒否する。

---

## 7. 歩く順番の雛形（出町柳）

| 役割 | 意味 | 出町柳の例 |
| --- | --- | --- |
| landform | 地形・水・土地の骨格 | 鴨川デルタ（合流の地点名） |
| landmark | 名所・土地の顔 | 下鴨神社 |
| town | いまの生活の導線 | 枡形商店街 |

他駅では **役割だけ借り、固有名は出町をコピーしない**。  
町場が無ければ town を出さない（1〜3件でよい）。

川名だけのスポット名は禁止（「淀川」→「淀川の堤防」等、歩いて立つ地点名）。

## 8. データの作り方と料金

| 種類 | 内容 |
| --- | --- |
| 編集シード | 人手で厚みを入れた駅（出町柳など） |
| AI 生成 | 未収録駅 → Gemini（検索 grounding）等で徒歩圏 JSON |
| 共有キャッシュ | 同じ駅の再生成を減らす |
| 座標ロック | 誤ピンが致命的な店はロック JSON で固定 |

| 道 | 内容 |
| --- | --- |
| コイン | 新規／作り直し 1回＝1コイン。保存の再オープンは0。**買い切り後も使える** |
| BYOK | 買い切り後、自分の API で生成可。API 設定後もコイン経路に切替可 |

物語HP: https://lagado.jp/mishiranu-orikata/

## 9. 既知の限界（評価用に明示）

1. 地図精度は完全ではない（ゲートとロックで致命傷を減らす）。  
2. AI 案内に幻覚リスクはある（grounding・関所で抑えるがゼロではない）。  
3. ナビ・リアルタイム混雑・公式時刻表は扱わない。  
4. 営業の鮮度は弱い。  
5. 天気・同行者・体力・治安感覚はユーザー側。  
6. 無料輪郭は MapKit の見える範囲に依存し、**都市駅では店密度の一文に落ちることがある**。  
7. DEBUG 実機は Mac の開発サーバー（LAN）に依存しうる（本番は別ホスト）。

## 11. 他AIへの問い（そのまま貼ってよい）

忖度せず、**「知らない駅で降りられるか」**だけを軸に答えてください。

1. **ドアが閉まる前（数十秒〜2分）に、この仕様は降りる決断を助けられるか。** 効くならどの段か。足りないなら最小の追加は何か。  
2. **無料輪郭→有料詳細の二段は妥当か。** 輪郭が薄いとき「材料不足を認めて詳しくへ進む」設計は、ユーザーを安心させるか／不安にさせるか。  
3. **空白の駅（店0）を「風景を歩く駅」として肯定する方針は、降りたあとの落胆を減らせるか。** リスクは何か。  
4. **撤退ライン（徒歩分・railHint）は、改札を出る無意識のブレーキを外せるか。**  
5. **地図の unverified 非表示＋1.5km ゲートは、誤案内リスクに対して十分か／厳しすぎか。**  
6. **ナビなし・口コミなしでも「降りて歩く」用途として足りるか。** 足すなら最小1機能は何か。  
7. **総合:** 「見知らぬ駅でも降りてみよう」と思えるプロダクトか。**10点満点**と、**一番の弱点を1つ**。  
8. **やらないでほしいこと:** UIのダッシュボード化、機能の山積み、営業APIや時刻表APIの即導入提案（必要なら「将来・任意」と分けて書く）。

## 13. 一文の総括（作者意図）

> 知らない駅で降りられない主因は勇気ではなく、徒歩圏の情報不足と、ドアまでの時間・空白・撤退への不安である。見知らぬ駅は、無料の輪郭で決断を助け、コインで詳しい順番を開き、空白を失敗にせず、すぐ戻れる距離を示して、ホームに立った人の次の一歩を出すためのアプリである。
